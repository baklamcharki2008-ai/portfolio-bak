# MASTER PROMPT: WhatsApp Clone

## Project Overview
Build a secure real-time messaging application with end-to-end encryption, voice/video calls, status updates, group chats, media sharing, and multi-device support.

## Tech Stack
- **Frontend:** React Native (Expo) for mobile, Next.js 14 for web, TypeScript, Tailwind CSS, React Native Reanimated
- **Backend:** Node.js + TypeScript, Express
- **Database:** PostgreSQL (metadata), ScyllaDB (messages), Redis (presence + caching)
- **Real-time:** WebSocket cluster with custom protocol
- **Voice/Video:** WebRTC + mediasoup SFU
- **E2E Encryption:** Signal Protocol (libsignal-node)
- **Auth:** Phone number verification (Twilio)
- **Storage:** Cloudflare R2 with client-side encryption
- **Push:** Firebase Cloud Messaging + APNs
- **Infrastructure:** Docker, Kubernetes, Terraform, GitHub Actions
- **Monitoring:** Prometheus, Grafana, Sentry, DataDog

## Detailed Requirements

- Signal Protocol implementation

- X3DH key agreement protocol
- Pre-key bundle management
- Ephemeral key rotation
- Perfect forward secrecy
- Cryptographic identity verification (security code)
- Encryption for group chats (Sender Keys)
- E2EE for media attachments
- E2EE for voice/video calls (SRTP)

### Database Design

Core tables:
- users (phone, name, about, profile_pic, settings)
- devices (device_id, public_key, last_active)
- pre_keys (key_id, public_key, device_id)
- signed_pre_keys (key_id, public_key, signature)
- conversations, conversation_participants
- messages (id_64bit, conversation_id, sender, content_type, encrypted_payload)
- message_statuses (message_id, user_id, status: sent/delivered/read/played)
- message_reactions, message_replies
- groups, group_members, group_settings
- calls (type, participants, duration, status)
- stories, story_views
- contacts, blocked_users

Message storage:
- Partition by conversation_id + month
- ScyllaDB for horizontal scalability
- Archive to cold storage after 6 months

### API Structure

```
WebSocket Protocol (binary, custom framing):
  Frame structure: [type:1][length:4][payload:variable]

Types:
  MESSAGE_SEND        - Send encrypted message
  MESSAGE_RECEIVE     - Receive new message
  MESSAGE_ACK         - Delivery/read acknowledgement
  TYPING_START        - Typing indicator
  TYPING_STOP         - Stop typing
  PRESENCE_UPDATE     - Online/offline/last_seen
  CALL_INITIATE       - Start voice/video call
  CALL_SIGNAL         - WebRTC signaling (SDP/ICE)
  KEY_EXCHANGE        - E2EE key exchange
  DEVICE_SYNC         - Multi-device synchronization

REST:
  POST /v1/register          - Register phone number
  POST /v1/verify            - Verify OTP
  GET  /v1/contacts          - Sync contacts
  POST /v1/media/upload      - Upload encrypted media
  GET  /v1/media/:id         - Download media
  GET  /v1/stories           - Get contact stories
```

## Final Instructions
Build a complete WhatsApp-like messaging platform with true end-to-end encryption. The Signal Protocol implementation must be cryptographically sound and audited. Voice/video call quality must match carrier-grade standards. Support seamless multi-device experience with message sync. Ensure all messages are encrypted and the server cannot read message content. Design the system for global scale with regional data centers. Make the UI buttery smooth with 60fps animations. Implement proper iOS/Android notification channels with rich media.
